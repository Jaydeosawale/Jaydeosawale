# Security Policy

## Reporting Security Vulnerabilities

🔒 **Please do NOT open public issues for security vulnerabilities.**

If you discover a security vulnerability, please report it responsibly:

### How to Report

1. **Email:** Send details to your security contact
2. **Include:**
   - Description of the vulnerability
   - Steps to reproduce
   - Potential impact
   - Suggested fix (if any)

### What to Expect

- Acknowledgment within 48 hours
- Regular updates on progress
- Credit in security advisory (if desired)
- Coordinated disclosure timeline

---

## Security Best Practices

### For Users

- Keep dependencies updated
- Review code before using in production
- Report vulnerabilities responsibly
- Follow secure coding practices

### For Contributors

- Use security-focused code reviews
- Test for common vulnerabilities
- Keep dependencies current
- Document security considerations

---

## Supported Versions

- Latest version receives security updates
- Previous major version may receive critical fixes
- Older versions: no guaranteed support

---

## Security Advisories

Security vulnerabilities that are fixed will be announced in GitHub Security Advisories.
